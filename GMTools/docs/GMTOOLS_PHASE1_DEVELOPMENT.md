# GMTools 第一阶段开发文档：基础地震动格式转换

> 上级项目：EETB  
> 子项目：GMTools  
> 文档类型：阶段开发任务说明  
> 依据：《EETB 项目介绍与基本原则》  
> 阶段目标：实现**单文件读取、多通道预览、单通道逐文件导出**的可用闭环

## 1. 开发目标与完成定义

第一阶段不追求格式数量最多，而是实现一套小而稳定、后续容易添加格式的核心机制。目标用户应能：

1. 选择一个文件，自动检测格式或手动指定格式。
2. 对标准文件自动提取可识别的采样间隔、样本数、单位和通道信息；对通用文本通过简明选项指定数据布局。
3. 查看原始文本预览（针对文本格式）和解析出的全部通道时程，检查参数和错误提示。
4. 选择目标格式与输出目录；一个输入文件的多个通道逐条写入独立文件。
5. 使用相同核心代码，通过 CLI 完成查看信息与转换操作。

**最小可用闭环优先级**：通用文本 + PEER AT2 + CLI + 最小 GUI + 单通道文本/AT2 导出应最先贯通；随后同阶段增补 SAC 和 miniSEED 的标准适配，不让某一复杂格式阻塞基础平台。

## 2. 本阶段功能范围

### 2.1 格式支持清单

| 格式 | 输入 | 输出 | 开发顺序与限制 |
|---|---|---|---|
| 通用 TXT / DAT | 必须 | 必须 | 最先完成，数值文本 |
| CSV / TSV | 必须 | 必须 | 采用通用文本按列解析；输出为单通道文件 |
| PEER NGA AT2 | 必须 | 必须 | 解析 NPTS、DT、物理量与单位；输出符合目标格式 |
| SAC Binary | 本阶段目标 | 本阶段目标 | 独立二进制适配器，先保证常见等间隔数据，明确不支持范围 |
| 标准 miniSEED 2/3 | 本阶段目标 | 本阶段目标 | 优先评估 libmseed；分版本验证，仅承诺实际测试过的编码和版本 |
| 已有特殊 miniSEED 变体 | 条件性读取 | 暂不要求 | 有可用样本、许可和可复用逻辑时引入，不阻塞阶段验收 |

说明：表中“本阶段目标”表示计划在基础闭环建立后逐项完成；如出现明显超出预期的依赖或格式差异，应记录剩余事项，不为了宣称兼容而写不可靠的适配。阶段最小验收以“必须”项为准，SAC / miniSEED 需各自有明确的完成记录。

**本阶段不包含**：跨文件合并、一个输出文件写入多个通道、COSMOS/SMC/K-NET 完整适配、复杂固定宽度/Fortran 全覆盖、全自动文本语义推断、滤波/积分/重采样、批量任务管理、频谱或反应谱分析。

### 2.2 单文件输入与逐通道输出

- 上层读取一份文件的原始字节；Format Reader 接收字节视图与解析参数。
- 一个 Reader 返回 `FileData`，其中含动态数量的 Trace；1 条和多条按相同代码路径处理。
- 每个 Writer 仅接受一条 Trace，输出一个文件；默认导出全部 Trace，允许指定子集。
- 输入目录的批量读取不在本阶段范围；CLI 可以多次调用命令处理不同文件。
- 不按文件名、通道名或台站信息跨文件自动配对、合并或时间对齐。

## 3. 核心数据模型

概念结构如下（示意代码，不要求照搬类型细节）：

```cpp
struct Trace {
    std::string name;                       // 可为空，输出时可生成 CH01 等安全名称
    std::vector<double> samples;            // 一个通道的数值
    std::optional<double> dt_seconds;       // 等间隔采样间隔
    std::optional<TimePoint> start_time;    // 已知绝对起始时刻时使用
    PhysicalQuantity quantity;              // Unknown / Acceleration / Velocity / Displacement / Counts
    Unit unit;                              // Unknown / G / Mps2 / Cmps2 / ...
    Metadata attributes;                    // 仅保存有价值的格式扩展属性
};

struct FileData {
    std::vector<Trace> traces;
    FormatId source_format;
    Metadata attributes;                    // 文件级元信息
};
```

#### 3.1 必须遵循的规则

- `samples.size()` 是实际样本数。头段的 `NPTS` 是校验来源，而非用来静默调整数组。
- `dt_seconds` 为可选正有限数；没有可靠依据时保持未知。
- `start_time` 用于绝对时间；纯相对时间数据不应伪造日期。若需要保存相对起点，可由后续最小扩展字段表达。
- `quantity` 与 `unit` 相互独立但校验组合合法性；单位未知时可显示原数值，不作物理换算。
- 每个 Trace 独立保存所有属性，不建立跨 Trace 的共同采样率/单位要求。
- 每个文件和 Trace 都可有命名空间式扩展属性，例如 `sac.kstnm`、`peer.event`；优先采用组合而非派生类。
- 等间隔波形为第一版的通用数据表达。无法可靠表示的不等间隔数据应给出不支持诊断；不自行取平均 `dt`。
- miniSEED 中同名通道的片段若时间不连续或重叠，不能静默补零、覆盖或拼接；可以保留为多条独立 Trace，并使用稳定序号区分。

#### 3.2 单位与数值处理

首批加速度预设：

| 内部枚举（建议） | 界面显示 | 对应关系 |
|---|---|---|
| `G` | g | 1 g = 9.80665 m/s² |
| `Mps2` | m/s² | 1 m/s² = 100 cm/s² |
| `Cmps2` | cm/s² | 1 cm/s² = 0.01 m/s² |

- 默认保存解析得到的数值与其真实单位，不强制在导入时改成某个单位。
- Writer 可在目标格式有明确单位要求时进行临时转换，不改变内存中的原始 Trace。
- 原始数字计数转换为物理量必须有可靠标定信息；不将 Counts 直接解释为 g。
- 头段提供的标定系数、单位换算、用户调幅在语义和实现上分别处理。本阶段不要求单独实现用户调幅功能。
- 对 AT2 等明确要求加速度物理单位的目标格式，`quantity` 和 `unit` 不满足要求时拒绝写出并指出缺少什么。

## 4. Format Reader / Writer 与注册机制

### 4.1 输入接口

建议统一入口是一个字节视图（由文件加载层负责文件 I/O）：

```cpp
ReadResult read(
    std::span<const std::byte> bytes,
    const ReadOptions& options);
```

`ReadOptions` 可以包括显式 `FormatId`、通用文本解析规则、用户补充的时间/物理量/单位等；默认优先使用已知元信息。解析结果包含 `FileData` 和结构化诊断（错误、警告、来源），不要只返回 `bool`。

**不要把路径传给每个格式处理器作为其唯一入口**：路径读取、格式识别、文本解码、实际解析应可分离。首期允许一次性将文件完整读取到内存；暂不要求流式解析。

### 4.2 输出接口

```cpp
WriteResult write(
    const Trace& trace,
    const WriteOptions& options);
```

Writer 对单个 Trace 进行目标格式完整性校验、必要单位换算、字节编码；外层统一负责生成输出路径与写文件。Reader 与 Writer 独立登记，允许只读格式。

### 4.3 格式注册与检测

- 使用简单静态注册表或清晰的函数映射（格式 ID → Reader/Writer/检测函数），本阶段**不需要动态插件装载**。
- 识别顺序优先依据可靠的二进制标记或文本头段签名；扩展名作为辅助线索。
- 自动检测存在歧义时不要虚报确定性，允许 `--format` 或 GUI 下拉框明确指定。
- 普通文本作为合理的手动回退选项，但不能把任意二进制字节误当作文本成功解析。
- `formats` 命令展示读/写能力与支持边界，不宣称未经验证的版本和子类型。

## 5. 统一文本解析方案

**基本思路：已知文本格式提取元数据与解析规则，数值部分统一交给 Text Parser。** 不再把“标准文本”和“通用文本”设计成两套完整的波形读取器。

### 5.1 TextParseOptions（概念字段）

| 字段 | 含义 | 默认/要求 |
|---|---|---|
| `first_line` | 数据起始行，**1-based、包含该行** | 可自动判断，必要时手动填写 |
| `last_line` | 数据结束行，**1-based、包含该行** | 缺省为文件末尾 |
| `layout` | `Sequential` 或 `Columnar` | 由标准规则设置或用户选择 |
| `delimiter` | 空白字符、逗号、Tab（可自动判断） | 初始支持常见分隔 |
| `data_columns` | 使用哪些列；按列时每列一个 Trace | 起始实现可以用 1-based 列号 |
| `time_column` | 可选的显式时间列 | 缺省无；不得同时作为数据列 |
| `dt` / `fs` | 采样间隔或采样率，仅指定其一 | 优先来自可靠头段/时间列；否则可选输入 |
| `quantity` / `unit` | 物理量和输入单位 | 未知可保留，但导出受限 |
| `numeric_factor` | 有明确来源的数值标定/修正 | 默认 1；区分来源和语义 |

`Sequential`：把数据区的数值按**行优先**连续展开成一条 Trace，兼容“单列”和“每行多个连续采样值”。  
`Columnar`：每个选定的数据列生成一条 Trace，可选一列时间；兼容“单列”“时间+幅值”“多通道矩阵”“时间+多通道”。

注意：用户是否知道每行多个数属于一条时程，还是每列代表多个通道，是布局解释问题。**不能只根据列数擅自作出工程语义判断。**

### 5.2 标准文本预设

- 第一批明确实现 PEER NGA AT2。格式规则负责识别头段、提取 `NPTS`、`DT`、物理量/单位、定位数据起始行，并设置 `Sequential`。
- 标准格式的头段行数不必写死；优先依据规范标记解析。对 `NPTS` 与实际数量不一致、`DT` 缺失或非法的情况返回清晰诊断。
- CSV/TSV 优先按 `Columnar`，支持首行列名；无明确时间列时不强行推断第一列为时间。
- 后续扩展 SMC、K-NET 等时沿用“头段规则 + 公共数值解析”，但允许它们在存在特殊块结构、数字计数标定时执行少量独立代码。

### 5.3 文本读取边界

第一版优先支持 UTF-8/ASCII、常见换行形式、空白/逗号/Tab 分隔、普通浮点科学计数法、空行和明确的表头跳过。遇到非数值数据区、列数变化、文本尾段，应能指出具体行号。

GBK、Fortran `D` 指数、固定宽度数值、分段数据、复杂引号 CSV 等可在真实样本驱动下逐步补充；不要为了“兼容所有文本”堆砌自动猜测规则。

### 5.4 元信息来源与覆盖

- 已知格式头段或明确时间列提供有效值时自动采用，并记录其来源。
- 用户可显式补充缺失值，或有意识地覆盖原始值；覆盖须有可查看的记录和必要的冲突提示。
- `N` 由解析结果计算，`dt` 和 `fs` 互为换算，不要求用户重复输入。
- 校验显式时间列等间隔性（合理浮点容差）；不满足时报告非等间隔，而不是默默求平均间隔。

## 6. CLI 设计

第一阶段仅设三个主要入口：

```bash
# 检测格式与通道信息
gmtools info record.at2

# 查看支持格式及读写能力
gmtools formats

# 转换当前文件的全部通道
gmtools convert record.mseed --to csv -o ./out/

# 手动指定文本规则缺失的参数
gmtools convert record.txt --format text --to at2 \
  --dt 0.01 --input-unit cm/s2 -o ./out/

# 选择指定通道（序号为 1-based，具体名称以后再扩展）
gmtools convert record.mseed --to sac --channel 2 -o ./out/
```

建议参数：

| 参数 | 功能 |
|---|---|
| `--format` | 指定输入格式，默认自动检测 |
| `--to` | 指定目标格式，必需 |
| `-o, --output` | 输出目录；单 Trace 时可允许指定完整文件名 |
| `--dt` / `--fs` | 补充采样参数；互斥 |
| `--input-unit` | 指定/覆盖输入单位 |
| `--channel` | 选择一条 Trace；不指定则输出全部 |
| `--profile` | 读取保存的通用文本解析配置；可在文本 GUI 稳定后补齐 |
| `--overwrite` | 明确允许覆盖已有输出，默认禁止 |

输出规则：多条 Trace 时 `-o` 指向目录，采用 `{输入文件名}_{通道名或序号}.{扩展名}`；无名/重名通道使用稳定编号并避免冲突。建议在实际写入前检查全部目标路径是否冲突，失败返回非零退出码，不产出“看似成功”的文件。

CLI 不引入 `combine`、跨文件自动分组、工作流、任务数据库或多层配置包。

## 7. GUI 最小版本

### 7.1 整体布局

建议单窗口、三区域，不照搬 REST 的数据集/工作流结构：

1. **文件和通道列表**：当前导入文件，展开显示全部 Trace；可选择单个通道查看属性。
2. **数据预览**：默认展示当前文件的所有通道时程，可上下排列并独立纵轴；采样信息未知时允许按样本序号预览，不虚构秒轴。
3. **信息与导出**：显示/补充 dt、单位、通道名、格式信息，选择目标格式和输出目录、选择全部或部分通道并导出。

### 7.2 文本解析窗口

参考 SeismoSignal 的“预设 + 参数 + 原始文本”思路，但使用统一文本规则：

- 顶部选择自动检测、PEER AT2、通用 TXT/CSV 等预设。
- 提供数据起始行、可选结束行、`Sequential`/`Columnar`、数据列、时间列、采样间隔、输入单位等必要控制项；不同模式只展示相关设置。
- 显示带行号的原始文本（至少能够定位和突出数据起始行），允许检查头段。
- 参数变更后提供简洁的解析结果反馈：解析是否成功、Trace 数量、每条样本数、dt、单位及行号错误。
- 解析确认后进入主界面查看全部通道时程；**不要求在文本解析窗口再次实现完整绘图系统**。
- 自动提取字段仍可查看，并允许用户明确覆盖。标准预设应降低手动填写量，而非锁死参数。

### 7.3 GUI 一期不做

跨文件关联、目录批量任务页、频谱/反应谱、滤波面板、三分量合成、长期任务历史、复杂解析模板管理器。

## 9. 实施顺序与交付物

### M1 — 核心模型与读写抽象

- 建立 Trace、FileData、Quantity、Unit、Metadata、Diagnostics 的最小定义。
- 建立文件字节读取、Format Reader/Writer、静态注册和格式检测的基础接口。
- 实现输入/输出合法性检查、单位换算及文件命名规则。

**交付物**：可被 CLI/GUI 共用的核心库，明确的错误/警告返回形式。

### M2 — 通用文本与 PEER 闭环

- 实现 Text Parser 的 Sequential / Columnar 两种布局及相关解析参数。
- 实现 TXT/DAT、CSV/TSV、PEER AT2 的读取；PEER 头段信息提取与 NPTS/DT 校验。
- 实现单通道 TXT、CSV、AT2 输出；验证多通道输入可以分别导出。
- CLI 完成 `info`、`convert`、`formats`。

**交付物**：无需 GUI 也可可靠转换典型文本与 PEER 文件。

### M3 — 最小 GUI 与文本预览

- 单窗口文件/通道/参数/导出布局。
- 文本格式预设、原文行号预览、必要参数修改、解析诊断展示。
- 导入文件全部通道的基础时程展示；统一调用 M1/M2 的转换接口。

**交付物**：用户可以打开、检查、转换常见文件，不必通过 CLI 手动调参。

### M4 — SAC / miniSEED 增量适配

- 优先使用成熟库或已验证代码，分别实现 SAC Binary 和标准 miniSEED 2/3 的可验证输入。
- 符合目标格式要求、样本足够且依赖稳定时实现各自 Writer；记录具体支持版本、编码和局限性。
- 针对 miniSEED 的多记录块、重复通道、片段间隔/重叠等给出确定性处理和诊断。
- 评估 REST 既有特殊 miniSEED 变体；仅在明确格式差异和有真实样本时纳入。

**交付物**：新增格式能复用同一 Trace 与导出流程；未完成子类型明确列出，不阻塞 M1–M3 基础闭环。

### M5 — 集成核查与文档

- 检查 CLI/GUI 对同一输入使用相同底层读写路径和参数语义。
- 整理 `formats` 实际支持情况、典型命令、GUI 使用说明和已知限制。
- 使用少量真实文件完成下节验收，并修复发现的明确问题。

**交付物**：可以交付使用的基础转换工具及格式支持矩阵。

## 10. 精简验收计划

重点验证**读对、解释对、导出对**，以真实样本为主，不追求数量。

| 编号 | 样本/情形 | 验收要点 |
|---|---|---|
| T1 | 单列 TXT | 正确样本数；缺 dt/单位可读取但不伪造 |
| T2 | 多列连续数值 TXT / PEER AT2 | 按行优先展开；解析 NPTS/DT，数量冲突有诊断 |
| T3 | 时间列 + 幅值列 | 识别时间列并验证 dt；非等间隔不默默平均 |
| T4 | 多通道 CSV | 每列独立 Trace；全部预览；分别输出多个单通道文件 |
| T5 | 单位转换 | g、m/s²、cm/s² 三种单位相互转换正确；未知单位阻止需要物理量的输出 |
| T6 | SAC Binary | 常见等间隔文件读出样本、dt 与通道信息；若 Writer 实现则独立重读核查 |
| T7 | miniSEED | 标准文件中多个通道/片段处理正确，不静默填补时间缺口 |
| T8 | 文件输出冲突和解析错误 | 不静默覆盖；明确展示错误文件、行/通道和原因 |

**验收方式**：优先对输入输出样本数、dt、数值误差、单位和通道数进行比较；对可写目标格式，用相应 Reader 或独立工具重新读取。对于受编码精度影响的二进制格式，按编码精度设定合理容差，不机械要求逐字节一致。GUI 只做必要的人工交互核查；不额外开发大型视觉回归测试体系。

完成 M1–M3 且 T1–T5、T8 通过，即形成**阶段最小可用版本**。M4 的格式逐项验收 T6、T7 后标记为支持；任何未验证子类型必须保持未支持或实验性状态。

## 11. 风险与明确约束

- **文本布局歧义**：同一数值矩阵可能是连续样本，也可能是多通道；优先提供明确选择而非猜测。
- **标准文本头段差异**：不能简单固定 PEER 等格式的数据起始行；应依规范解析并反馈不符合预期的头段。
- **miniSEED 的单位缺失**：标准 miniSEED 通常不包含足以确定工程加速度单位的全部台站响应信息；未确认前保持 Unknown/Counts，不直接输出带有 g 单位含义的文件。
- **多片段波形**：无法可靠拼接时拆为独立 Trace 或提示不支持，不能静默补齐。
- **SAC/miniSEED 专有元信息**：部分字段无法通过通用 Trace 完整表达；使用扩展 Metadata 保留有意义信息，目标不支持时提示。
- **用户覆盖参数**：明确区分源数据、解析值和覆盖值；用户覆盖不应修改原文件。
- **内存策略**：首期按文件一次性读取字节和样本；大文件流式解析为后续性能优化，不先引入复杂抽象。
- **外部依赖与许可**：优先选择已有成熟库，但实际集成前检查版本、接口和许可证；复用 REST 代码时留意其模块边界和许可要求。

## 12. 本阶段不应做的事

- 不引入 Record Set / Ground Motion 层级或跨文件合并逻辑。
- 不将输入多通道重新写入同一输出文件。
- 不做隐式的滤波、零点修正、积分、重采样和三分量旋转。
- 不为每种文本格式编写一套相互重复的数值读取器。
- 不先建立复杂的动态插件框架、任务数据库、工作流配置系统。
- 不因追求“自动化”而推断无依据的单位、方向或时间。
- 不为了扩大测试规模而重复编写相同功能的测试；应优先解决真实数据发现的问题。

## 13. 开发完成后的文档更新

阶段完成后应同步维护：

1. 已支持的格式及版本、读/写能力、主要限制。
2. CLI 快速使用说明和常见错误处理。
3. GUI 导入、参数补充、文本预览与导出操作说明。
4. 关键真实样本的验证记录与仍未解决的问题。

**开发判定原则**：功能越少越要确保行为可信、结果可检查；每新增一种格式，应尽可能只是补充一个明确的适配规则，而不是改造核心数据模型。
