## 1. 背景与目标

第三阶段已经实现公共单位和标定机制、公共通道标识及时间编辑、标准与 Modified miniSEED 读取、SAC v6/v7、PEER AT2/VT2/DT2、通用文本输出和自描述文本回读，以及 CLI、GUI、xmake 的集成。

现有第三阶段验收记录表明，T1–T10 在所列 Linux 样本及操作范围内通过；其中 Modified 实录主要覆盖 `wc`，GUI 主要覆盖 Linux 离屏工作流，Windows、其他设备变体和 NIED 正式样本仍有明确的待验收范围。历史结果不等于本轮修复后已经重新验收。

本轮不继续扩大格式支持范围，不改变核心数据结构或主要交互流程。目标如下：

1. 自描述文本能够保留必要的标定、缩放和单位处理来源，回读后的数据不会因这些历史字段而再次执行转换或受到错误的单位约束。
2. Modified miniSEED 采用与标准 miniSEED 一致的时间连续性诊断原则，在允许范围内合并非零时间残差时保留可查证的信息。
3. 整理少量实际可复现的验收代码和说明，不将验收依赖、临时文件和大量测试产物纳入项目运行依赖。
4. 清理意外提交的附件副本，完善格式支持、当前限制和数据来源说明。

## 3. F1：自描述文本的数值处理来源

### 3.1 当前问题

`src/formats/text.cpp` 中的 `write_text()` 使用 `# GMTools waveform 1`、单行 JSON 元信息、列名与数值区保存波形；`read_text()` 可以直接回读。

当前头段保存样本数、名称、物理量、单位、dt、绝对首样本 UTC、相对起点、数据布局及部分公共通道标识，但不保存标定和调幅来源。`src/core/data.cpp` 中的 `process_read()` 已记录部分相关字段：

```text
source.original_unit
source.original_quantity
calibration.source
calibration.factor
calibration.applied_unit
text.numeric_factor
source.numeric_factor
```

其中 `text.numeric_factor` 是实际乘数，`source.numeric_factor` 主要描述来源和执行语义，二者不能混用。K-NET 的文件标定来源由其 Reader 保存，Modified 的标定信息还包含源灵敏度等格式专有字段。

例如将武汉 Modified 记录应用文件标定、两倍调幅并转换为 cm/s² 后导出带元信息的 CSV，回读能够恢复最终波形及工程单位，却无法说明该波形的标定与缩放过程。普通数值文本及标准二进制文件也不一定能表达这些信息，但本轮只要求在 GMTools 自描述文本中补齐。

### 3.2 设计原则：当前数值与历史来源分离

自描述文本中的 `quantity`、`unit` 等主字段始终描述**文件中实际保存的样本**。标定因子、调幅系数、原始单位和换算来源是**历史信息**，不作为下一次读取的执行参数。

特别注意，现有 `calibration.applied_unit` 还被 `apply_overrides()` 用于约束已标定 Trace 的单位解释。不能简单把旧字段原样恢复到当前生效的属性集合。例如标定结果为 m/s²，而导出已转换为 cm/s²；再次读取时不得因为历史标定单位为 m/s² 而拒绝正常解释 cm/s²，也不能将 cm/s² 波形再次乘以标定系数。

建议在自描述文本 JSON 中增加一个可选 `provenance` 对象，集中承载少量经过定义的历史信息，并在回读时映射至明确的历史属性命名空间（例如 `history.*`）。实际命名由开发者结合现有字段确定，无需为此增加新的公共类或通用处理链框架。

示意（非强制逐字采用的 JSON schema）：

```json
{
  "name": "WH.XY001..EIN",
  "npts": 240000,
  "quantity": "acceleration",
  "unit": "cm/s²",
  "dt": 0.005,
  "provenance": {
    "original_quantity": "counts",
    "original_unit": "counts",
    "calibration": {
      "source": "Modified miniSEED",
      "factor": 0.00002,
      "unit": "m/s²"
    },
    "numeric_factor": 2.0,
    "unit_conversion": {"from": "m/s²", "to": "cm/s²"}
  }
}
```

上例省略了现有时间、标识和布局字段，仅说明历史信息的组织关系，不是完整可读取文件。

### 3.3 实施要求

- 优先保存原始量/单位（已知时）、实际标定来源和因子、因子的物理单位、已应用的数值缩放，以及导出单位变化（发生时）。不保存未经应用的建议灵敏度作为已执行标定；如保留候选灵敏度，需明确其为参考信息。
- 统一提取已实际执行的处理信息。Modified、手动标定及 K-NET 的来源应基于各自现有真实字段，不推断缺失的系数，不伪造设备计量溯源。
- 核对 `registry.cpp` 中单位换算使用临时 Trace 副本的路径。若需要保存本次换算来源，仅更新用于写出的副本或等价的输出元信息，不修改 GUI 当前 Trace、输入文件或其他待导出通道。
- 保留现有 v1 头段和必需字段。新增 `provenance` 为可选扩展；旧文件没有该字段时按原规则读取。若实现确实需要不兼容的格式变化，应先说明理由，不在本轮无必要地升级格式版本。
- 对已知历史字段进行类型、有限性、单位及结构检查。遇到无效信息时给出明确诊断，不把损坏的历史记录误当作有效标定。未知扩展字段不参与计算。元信息 JSON 中的当前数据解释仍由原有主字段校验。
- 回读只恢复当前波形及其历史记录，不自动执行历史标定、缩放或单位转换。对已明确为物理量的波形仍禁止错误地当作原始 counts 进行重复标定；已知 counts 的保护不能因历史字段的引入而失效。单位重标记与实际换算仍遵循原有规则。
- 若再次显式调幅或换算，应保留先前已有的有效历史，不能把原始标定来源覆写为新导出过程。可采用简单的既往记录与本次处理记录，或少量有序记录；无需设计完整审计系统。仅保存真实发生的操作，不为默认值或未执行动作制造记录。
- 原始或已缩放的 counts 应仍按其实际语义显示；若已经调幅，不得声称是未经修改的原始整数样本。对于再次导入的自描述文本，不将历史标定来源错误显示为本次新应用的标定。
- 保留单行 JSON 头段及原有 NPTS、时间网格、相对起点与 UTC 校验；普通 TXT/CSV、PEER、SAC 与 miniSEED 的读写默认行为不变。

### 3.4 CLI、GUI 与文档

CLI `info` 应能检查上述历史信息（可以通过已有 Metadata 输出呈现）。GUI 继续使用当前 Summary/Metadata/Diagnostics 页面；对历史标定与本次读入标定使用可区分的说明，不新建页面。

调整自描述文本的导出说明：明确保存的是基本波形元信息及所支持的数值处理历史，而非全部格式专有字段。若其他有意义的属性未写出，必要时提供简明提示。README 补充新增可选字段的意义及兼容规则，并说明回读不会自动再次处理数值。

参考实现位置：`src/core/data.cpp`、`src/formats/registry.cpp`、`src/formats/text.cpp`，必要时涉及 `src/formats/knet.cpp`、`src/gui/main_window.cpp` 和 CLI 信息展示。优先局部修改，不改变 `Trace` 固定成员。

## 4. F2：Modified miniSEED 时间连续性诊断

### 4.1 当前问题

`src/formats/modified_mseed.cpp` 已独立解析 BTime 与时间修正，并在通道标识、采样间隔、灵敏度、排列及包类型一致时，采用以下时间容差判断相邻记录是否可合并：

\[
\varepsilon = \min(10^{-4}\ \mathrm{s}, \Delta t/16)
\]

该判断适用于当前已支持的专有头段时间精度与数据模型。现有标准 miniSEED Reader (`src/formats/mseed.cpp`) 则在接受非零时间残差时记录最大残差并提供诊断。Modified Reader 目前没有保存同类信息，用户难以区分完全连续和容差内合并的情况。

### 4.2 修复内容

保留现有分段与合并条件，不调整当前阈值，不引入时间校正、重采样、补点或排序。

对于当前 Trace 已有 N 个样本、采样间隔为 dt 的情形，下一记录期望起点为 `start + N * dt`。比较实际下一记录起点与该期望值，得到合并残差。计算应沿用现有高精度时间差路径，避免先将两个绝对时刻转成低精度浮点秒再相减。

- 仅对实际被接受并合并的记录累计最大绝对起点残差；建议字段 `modified.max_start_residual_ns`，与现有 `mseed.max_start_residual_ns` 保持相同单位。纳秒整数或等价的精确表达需明确舍入规则。
- 如果出现非零且在容差内的有意义时间残差，给出带通道及记录定位信息的警告，说明样本保留、时间偏差在容差内、Trace 仍使用首样本与等间隔时间轴。避免由浮点乘法舍入尾数产生虚假的纳秒级告警；阈值处理与单位应明确。
- 警告数量应可控，每个 Trace 对同类容差合并问题给出一次提示或在结束时汇总，不为每个记录块重复输出；最大残差仍应完整累计。
- 新分段独立初始化残差统计；超容差、未知 BTime、采样参数或标定字段变化继续按原逻辑分段，不将这些残差错误计入已合并片段。
- 保留原有异常诊断、解码值和标定规则。可在既有 Summary 或 Metadata 页面显示最大残差，不增加绘图或界面框架。标准 miniSEED Reader 不做不必要的重构；必要的共享辅助函数应保持小规模。

### 4.3 验收关注点

使用真实武汉记录和少量由其派生的记录块（不修改原件）验证：完全连续、容差内非零偏差、超容差以及未知时间。其中应选择采样率允许实际 BTime 时间量化形成容差内非零偏差的用例，不人为制造协议无法表达的时间值。

检查通道数、各片段样本数量、数值、绝对首样本时刻与第三阶段行为保持一致；新增残差统计与独立计算一致。只检查本轮改动相关的时间情形，不重新覆盖全部 miniSEED 编码组合。

## 5. F3：验收结果的精简复现

### 5.1 当前问题

第三阶段验收记录提供了独立参考值、真实文件哈希、构建参数和实际运行结果，但主要脚本 `build/phase3/check.py` 与 `build/phase3/edges.py` 位于被忽略的构建目录。仅凭仓库中的复现示例，不能重新执行所有独立比较。

本轮不要求把完整临时测试过程迁移为长期维护的测试框架，也不要求全部 T1–T10 一键复现。

### 5.2 整理方案

若本地仍保留原验收脚本，先查看并提取其中最稳定、最有价值的独立核验逻辑，建议维护一个精简脚本，例如 `scripts/verify_core_formats.py`，以及简短使用说明。实际文件位置可沿用项目中合适的惯例。

优先覆盖：

| 核验内容 | 样本/参考 |
|---|---|
| AT2 与普通文本 | Helena、Trinidad；独立读取数值区和采样参数 |
| SAC | 现有台湾台站文件；独立读取或 ObsPy 核对样本、时间及头段 |
| 标准 miniSEED | 花莲记录；可选 ObsPy 核对通道数、样本数、采样率和数值 |
| Modified miniSEED | 用户提供的武汉文件；独立解压参考与标定公式（可选） |
| 本轮修复 | 自描述文本历史信息回读不改变数值、时间残差统计（少量必要用例） |

脚本要求：

- 通过参数接收已构建的 `gmtools` 可执行文件路径、示例目录、输出目录及可选外部样本路径；不要依赖开发者机器的绝对路径、临时 SDK、工作区目录或预设环境变量。
- 尽可能使用标准 Python 库读取文本和比较数值。需要 ObsPy 时明确声明为可选的验收依赖，与正式 Core/CLI/GUI 无关；缺少依赖或外部样本时明确显示 `SKIPPED` 或 `BLOCKED` 及原因，不报告 `PASS`。
- 独立核验输入数据与目标数据，不以 GMTools 自写自读作为唯一依据。精度应符合输出表示能力（例如 float32），时间误差应结合采样间隔和格式精度说明。
- 使用独立输出目录，保护原件，保留失败的诊断。对于实际已执行的断言失败应有非零退出状态；区分未执行、跳过和失败。
- 不自动下载需登录或再分发权限不明的数据；只允许用户提供本地文件路径。对已记录的真实样本，可核查哈希并明确提示样本是否与历史基线一致。
- 不提交大型日志、派生波形、GUI 截图、个人环境配置及完整测试产物。若原脚本已不存在，应依据现有验收文档重建少量关键检查，并明确无法完整复现的范围；不得虚构已取得的文件或历史执行证据。
- 本轮只负责整理/编写复现入口。未获明确授权，不实际运行验证脚本。README 或验收文档应给出可用命令示例、依赖和输入要求；命令中使用实际实现的参数。

F1 与 F2 相对独立，可以按实际开发安排先后实施。避免将这轮收尾扩展为批量转换、版本发布或重新设计数据模型的开发工作。

## 8. 精简验收方案

以下内容是用户后续核查或明确授权后的运行验收计划，不授权自动运行。优先使用已有四份示例及武汉本地记录，不建设独立的大型测试体系。

| 用例 | 输入与操作 | 预期结果 |
|---|---|---|
| C1 历史标定及调幅 | 武汉加速度通道应用文件标定、两倍调幅、输出 cm/s² 自描述 CSV | 样本与独立 `counts × 100 / sensitivity × 2 × 100` 一致，头段单位 cm/s²，历史标定单位 m/s²，因子和缩放正确 |
| C2 回读与再次转换 | 回读 C1 并保持单位，再输出 g 或再次显式调幅 | 无重复标定/缩放，无历史单位锁冲突；新值及历史信息正确；不能将已标定波形误作原始 counts |
| C3 原有文本兼容 | 无 provenance 的旧 v1 文件、Trinidad Profile、普通 TXT/CSV | 原有解释和默认输出保持；无历史字段不构成错误；异常新增字段有明确诊断 |
| C4 Modified 时间 | 完全连续、容差内偏差、超容差、未知 BTime 的少量包 | 原有分段与样本保持；只统计已合并残差，诊断可定位且数量受控 |
| C5 复现入口 | 四份仓库样本、可选武汉样本及可选 ObsPy | 依赖和数据路径可配置，独立参考比较明确，缺少样本/依赖不误报通过 |
| C6 用户人工检查（按需） | GUI 查看已标定记录和自描述文本回读的 Summary/Metadata、导出 | 当前物理量与历史标定信息区分清楚，无新增无关界面操作 |

武汉验收参考值见 `docs/validation/GMTOOLS_PHASE3_RESULTS.md`：EIN 通道 240000 点、dt=0.005 s，低 30 位灵敏度编码为 5000000，对应 `0.00002 (m/s²)/count`。原始计数及时间应以实际样本与独立参考核对，不假定其他设备的同类文件使用相同参数。

例如，授权运行时可按现有命令进行 C1：

```bash
# 在 GMTools/ 下执行；$WH_RECORD 为用户提供的原始武汉文件路径
xmake run gmtools convert "$WH_RECORD" --format modified-mseed --channel 1 \
  --calibration source --numeric-factor 2 --output-unit cm/s2 \
  --to csv --text-layout time-values --text-header metadata \
  -o build/phase3-closeout/calibrated.csv
xmake run gmtools info build/phase3-closeout/calibrated.csv
```

该命令只演示实际操作入口，验收仍需对照独立数值参考。输出路径须为本次专用且不存在冲突的路径；不使用 `--overwrite` 覆盖原件或历史验收结果。

## 9. 完成定义与交付说明
