> 阶段定位：**保持常用格式读写与数值处理能力稳定，完善中英文界面、程序设置、转换配置复用及多文件批量转换，提高日常科研使用效率。**

## 1. 背景与开发目标

前三个阶段已建立 `FileData / Trace` 数据模型、统一格式读写接口、通用文本解析及 Profile、公共物理量与单位换算、仪器标定、标准与 Modified miniSEED、SAC v6/v7、PEER AT2/VT2/DT2、自描述文本及有序数值处理历史等能力。GUI 已按职责拆分，支持后台解析及导出、波形包络和通道检查，项目统一使用 xmake 构建。

当前主要不足已从格式支持转变为使用便利性：界面以英文显示，缺少正式的语言与主题设置入口；Profile v1 主要保存通用文本的输入解释规则，尚不能完整复用标定和输出配置；CLI 与 GUI 仍以一次处理一个输入文件为主，同类数据需要反复配置和转换。

本阶段目标：

1. 建立 Qt 原生国际化机制，提供简体中文、英文及跟随系统的语言选项，保存用户配置；同时完善少量全局外观与使用偏好设置。
2. 建立轻量、独立、版本化的转换预设（Conversion Preset），统一复用输入解释与输出参数，保留既有 Profile v1。
3. 实现多输入文件的独立、顺序转换，可靠管理目标路径、覆盖保护、文件级错误、执行进度及结果。
4. CLI 与 GUI 共用预设和批量转换核心；新增界面直接遵循双语要求，保持单文件检查工作区及原有转换流程。
5. 更新构建、使用和验收说明，为后续使用体验与地震动分析功能建立稳定基线。

## 2. 开发范围与约束

### 2.1 基本原则

- 保留现有单文件读取、独立 Trace、单 Trace 单文件输出原则。批量转换只是对多个独立文件执行同一套规则，不建立跨文件数据集，不进行同步、合并或三分量配对。
- 保留 `load_file()`、`read()`、`write()`、`export_file()` 的主要职责及各格式已有解析算法、标定顺序、单位约束、输出保护和来源信息。批量功能仅增量完善文件计划与执行入口。
- Core 不依赖 Qt；CLI 与 GUI 共用核心配置序列化、校验和执行逻辑。翻译、设置、预设目录管理和任务展示属于 GUI 或对应入口，不进入格式适配器。
- 保留已有 CLI 命令、参数行为、Profile v1、自描述文本 v1 和既有单位、格式名称。没有充分理由不进行不兼容变更。
- 不增加新文件格式，不开发滤波、基线校正、积分、频谱、反应谱等信号分析功能，不改造现有波形绘图体系。
- 不引入 REST Workflow、复杂任务调度、并行多文件处理、持久任务队列、断点续传、数据库或插件体系。
- 仅使用 xmake；继续保留标准 miniSEED 的可选 libmseed 依赖和精简 CLI 构建方式，不主动修改现有版本号或发布流程。
- 不自行运行测试、启动 GUI、进行截图或视觉检查、提交 Git；本文件中的验收方案不构成执行授权。可按任务安排进行必要静态检查与编译，如实记录执行情况。尽量复用已有样本和核验脚本，不增加大量测试。
- 开始前检查工作树、最新提交和用户已有更改。如实际基线不同，先核对差异，保留已有有效实现，不重复开发。

## 4. M1：GUI 国际化

### 4.1 实现方式

采用 Qt 原生翻译系统，英文作为源字符串，维护简体中文 `.ts` 文件，经 `lrelease` 生成 `.qm`，由 `QTranslator` 在程序启动时加载。英文模式直接使用源字符串，不另行维护一份英文译文。

- 使用 `tr()` 或明确上下文的 `QCoreApplication::translate()`；非 QObject 类、自由函数及静态选项使用合适的翻译上下文。不要使用按英文字符串查找的自建翻译表。
- 动态文字使用 `%1`、`%2` 等占位符及 Qt 对复数的支持，不通过拼接几个已翻译片段来构造难以翻译的句子；格式化数字与技术标识保持明确。
- 所有新增 GUI 文本从开始即纳入翻译，维护 `translations/gmtools_zh_CN.ts`。开发者使用 `lupdate` 显式更新源文本清单、维护译文；普通构建只需编译现有翻译文件，不反复修改已提交的 `.ts`。
- 自有 `.qm` 随 GUI 产物提供，建议嵌入 Qt Resource，或采用确定的安装路径；不能依赖当前工作目录或开发者个人 SDK 绝对路径。Qt 标准对话框、按钮等可加载 SDK 提供的相应 Qt 翻译资源（如 `qtbase_zh_CN`），原生系统文件选择器的语言仍可能由操作系统决定。
- 翻译对象生命周期覆盖整个应用运行期，加载发生在主窗口和其他常驻控件创建之前。资源缺失应提供明确诊断并回退英文，不导致启动失败；正式打包则不得漏掉自身翻译资源。

### 4.2 语言设置与生效方式

| 保存值 | 显示 | 含义 |
|---|---|---|
| `system` | 跟随系统 / System | 根据 Qt 系统 locale 选择支持语言 |
| `zh_CN` | 简体中文 | 固定中文 |
| `en_US` | English | 固定英文 |

默认 `system`，中文系统使用现有简体中文译文，其余未支持语言回退英文。不翻译配置值本身。语言选择控件中的语言名称使用各自语言，保证切换到任何语言后都能找到对应入口。

本阶段允许**重启后生效**，这是低成本的默认实施方案。设置窗口保存新语言后提示“重新启动程序后生效”，不强制退出或自动重启。当前已导入波形与任务状态不应因保存设置而丢失。如果实现实时切换，必须完整覆盖已创建窗口、动态标签、菜单、状态栏、对话框及图轴，并保持当前记录、编辑和任务状态；不为此大规模重构。默认不要求实时切换。

### 4.3 翻译范围

必须覆盖主窗口欢迎页、工具栏、操作按钮、导入配置、预览信息、通道列表、Summary/Metadata/Diagnostics 区域、通道属性编辑、输出格式选项、进度与结果、普通对话框、错误/确认提示、空状态、可访问性名称、工具提示、波形轴标题，以及本阶段新增设置、预设和批量界面。

以下内容保持稳定、不因界面语言而改变：

- 文件名、路径、用户输入内容、波形名称、台站代码、NSLC/SID。
- 格式名（miniSEED、SAC、PEER AT2 等）、单位符号及科学技术缩写。
- Core 枚举的序列化值、Profile/Preset JSON 字段、CLI 命令与参数、`info` 等原有输出及脚本可解析字段。
- 原始 Metadata 键值、底层诊断原文及来自操作系统/库的原始错误详情。

格式和单位下拉框必须将内部枚举或稳定值保存在 item data 中，界面标签只用于展示，不能从翻译后的文本反推选项。物理量、标定模式、通道筛选等可显示本地化标签，但写入 JSON 和传给 Core 的值不变。

Core 的 `Diagnostic.message` 仍保持现有英文，避免引入 Qt 或本轮大范围重构诊断结构。中文界面翻译诊断严重程度、阶段、操作失败标题和常见 GUI 自身提示；底层详情允许保留英文并可复制。禁止通过英文整句匹配来猜测错误原因。完整 Core 诊断本地化可在以后有需要时以稳定诊断代码与参数独立设计。

### 5.1 设置入口与内容

主窗口工具栏或标题区域新增统一的“设置 / Settings”入口，使用轻量对话框；未导入文件时同样可用。暂不建设多级设置页面。

| 分组 | 设置 | 默认值 |
|---|---|---|

| 外观与语言 | 主题：跟随系统 / 浅色 / 深色 | 跟随系统 |

主题延续现有 `theme.cpp` 的 Fusion 与配色方案，在选择浅色或深色时明确应用对应 palette，跟随系统仍使用启动时的系统配色判断。主题也可采用重启后生效；不要求随系统实时变化。避免新增第三方主题库或改动已有视觉风格。

### 5.2 持久化方案

沿用 `QSettings`，保留现有组织名 `EETB`、应用名 `GMTools` 和窗口状态、分隔比例等键。建议新增：

```ini
[ui]
language=system
theme=system
[preferences]
rememberDirectories=true
rememberConversionSettings=true
```

键名可结合代码惯例调整，但应稳定并在文档中明确。无配置或无效配置回退默认值。保存、取消应有明确行为；取消不修改持久配置。若用户关闭记忆功能，不再读取或写入相应最近值，清除旧记录或明确提供一致的忽略规则。

最近转换设置只用于恢复通用表单值或最近选用预设，不应自动对新文件执行标定或开始转换；加载文件时仍需确认输入解释。不得把上一次文件的 UTC、NSLC/SID、通道显示名、具体通道序号、临时路径、覆盖许可、执行进度或编辑状态自动复用于下一个文件。覆盖开关每次新批次/新输入默认关闭。

个人设置与可移植配置分离：程序外观、最近目录及偏好属于 QSettings；可分享的转换规则属于独立 JSON，不依赖 Qt 或用户配置文件。任务运行期间禁止修改可能影响当前执行的设置，避免隐式重启或切换资源。

## 6. M3：转换预设

### 6.1 定位与配置边界

现有 Profile v1（解析配置）仅用于通用文本输入解释，`profile.cpp` 明确限定其字段范围。本阶段新增 Conversion Preset（转换预设），负责复用一次完整转换的输入与输出规则。二者概念上独立，保持旧 Profile JSON 和 `--profile` 行为。

内部可采用组合而非继承：

```cpp
// 概念示意；最终命名及公开接口按当前实现统一。
struct ConversionPreset {
    std::string name;
    ReadOptions read;
    WriteOptions write;
    ChannelSelection selection; // 仅通用导出筛选规则，见 6.4
};
```

不直接序列化所有 ReadOptions/ExportOptions 字段；只定义白名单。不得保存特定输入或输出文件路径、扩展名提示、用户目录、覆盖权限、实际波形、具体台站或时间编辑、临时数据、任务结果。尤其 `MetadataEdit` 中的绝对/相对起点、NSLC/SID、清空操作等均为文件相关信息，不能默认传播到整批输入。

`ReadOptions.selected_channel` 表示对一条通道应用读取覆盖与处理参数，不等同于导出通道列表。不得将它直接混入通用导出筛选，避免读取和写出选错通道。

### 6.2 JSON v1

建议新增独立的预设 schema，而不是无条件将 Profile v1 扩展为另一种含义。以 `kind` 明确区分类型，`schema_version` 为整数 1。示例：

```json
{
  "kind": "gmtools-conversion-preset",
  "schema_version": 1,
  "name": "Modified miniSEED to engineering CSV",
  "read": {
    "format": "modified-mseed",
    "calibration": "source"
  },
  "write": {
    "format": "csv",
    "output_unit": "cm/s2",
    "text_layout": "time-values",
    "text_header": "metadata"
  },
  "selection": {
    "mode": "quantity",
    "quantity": "acceleration"
  }
}
```

各对象的建议字段：

| 对象 | 字段与说明 |
|---|---|
| 根 | `kind`、`schema_version`、`name`、`read`、`write`、可选 `selection` |
| read | `format`；`text` 中的 first_line、last_line、layout、delimiter、data_columns、time_column、numeric_factor；`overrides` 中的 dt/fs、quantity、unit；calibration、calibration_factor、calibration_unit、sac_standard_units |
| write | `format`（必填、非 auto）、`output_unit`（省略为保持输入单位）；text_layout、text_header、text_delimiter、precision、sac_version、sac_unit_mode、mseed_encoding |
| selection | `mode`：all 或 quantity；quantity 模式指定物理量 |

字段名可在实现时作少量一致性调整，最终 schema、示例、CLI 和 README 必须一致。输入单位接受现有单位别名，保存时统一使用稳定单位名称（不得使用翻译后的标签）。`numeric_factor` 仍沿用现有 Profile v1 在 text 中的字段位置，实际作用于公共读取处理流程；不重复另设一个调幅字段。

应复用 `profile.cpp` 已有 JSON 校验方法及现有枚举解析函数，避免在 Core、CLI、GUI 分别实现三套规则。可抽取少量共享 JSON 辅助函数，但不引入通用反射或配置框架。明确检查重复键、未知字段、非法版本、类型、数值范围、dt/fs 互斥、量纲、标定参数配套、目标格式与专有参数适用性。源文件内容决定的条件仍由 Reader/Writer 在执行时检查。已知格式在当前精简构建中不可用时，可读取预设以便迁移和查看，但必须在执行前报告不可用，不得静默替换格式。

预设保存使用现有安全文件写入机制或等价保护，非法文件不部分覆盖当前表单；加载失败保留原状态。已有 Profile v1 不迁移、不修改；允许在 GUI 载入 Profile 后补充标定/写出参数，再另存为新预设。

### 6.3 参数优先级与变更规则

统一采用“默认值 → 预设 → 本次明确设置”的顺序。CLI 使用显式参数存在性而不是仅比较最终值判断覆盖，例如显式 `--format auto`、`--calibration default`（若提供此选项）、显式恢复默认值必须与参数未出现区分；dt/fs 互相替换。

- 预设负责输入和目标规则；`-o`、`--overwrite`、输入路径及单文件元信息编辑只能在本次调用中设置。
- 预设和单独 `--profile` 在同一命令中互斥，避免两份配置来源之间产生隐含优先级。已有不带预设的 `--profile` 用法保持不变。
- CLI 显式 `--to` 可覆盖目标格式。发生目标变更时，只清除预设中已不适用于新目标的专有参数，并给出提示；本次明确传入但不适用的选项直接报错。公共输出单位继续按目标量纲与格式规则校验，不隐式重标记样本。建议增加 `--output-unit keep` 明确清除预设中的输出单位；该值仅表示不额外指定单位，PEER 等格式仍执行其强制输出单位。
- 改变输入格式后检查已有输入布局、标定和专有选项是否适用。不得把一个格式的标定或文本解释自动传播给不相容的格式；有冲突时明确要求用户调整，不能绕过 Reader 的原有约束。
- GUI 载入预设替换相应输入、输出与筛选表单，包括清空预设中缺失的可选字段。用户后续修改只影响本次任务，除非显式保存或另存。显示当前预设名称和是否已修改，不在每次编辑时覆盖预设原文件。

### 6.4 通道选择

批量默认导出全部 Trace，保留单文件多通道默认行为。实际监测文件可能同时包含加速度与辅助 counts（例如武汉 Modified miniSEED 实录），若预设要求统一导出 cm/s²，直接选择全部通道将触发正确的量纲拒绝。为满足该场景，本轮增加一种轻量的显式按物理量筛选规则，作为通用预设的可选项：

- `all`：全部通道，默认。
- `quantity`：在完整读取、标定及输入解释之后，按当前 Trace 的明确物理量选择通道，例如 acceleration；不从通道名或整数编码猜测物理量。对选中通道仍由 Writer 核查已知单位等条件。
- 未匹配的通道应明确列出或计数为未选择；若无任何匹配，标记该文件失败并继续批次，不能将空通道列表传给 `export_file()`（现有语义为空即全部）。
- 单文件 GUI 保留手动勾选与已有 `--channel N` 行为，具体通道序号不作为通用预设的默认字段；CLI batch 第一版不使用 `--channel N` 复用读取覆盖语义，不提供复杂的通道代码表达式。
- 筛选只作用于导出范围，不改变标定流程，不将未选中的异常通道隐式修复或忽略其已有读取错误。若整文件读取失败，则该文件失败。不要为此修改原始数据解释原则。

### 6.5 GUI 预设管理与使用

提供统一的预设管理入口（可为轻量对话框）。本机预设目录采用 `QStandardPaths::AppConfigLocation` 下的 `presets/` 或等价应用专用位置，CLI 不依赖该目录，使用显式 JSON 路径。

管理操作包括新建/保存、载入、另存、重命名、删除、导入外部 JSON、导出分享。默认仅删除本机管理的预设文件，外部原件不因导入或删除本机副本而改变。重名和同路径冲突应明确处理，不静默覆盖；内置预设只读，用户可复制后编辑。显示名可用中文或英文，但文件名安全处理、稳定内部标识和格式值不受语言影响。

建议提供少量内置示例（同一份配置语义、双语显示名称）：

| 预设 | 读取 | 写出及筛选 |
|---|---|---|
| 纯幅值 TXT | 自动识别 | TXT，无表头，保持单位，全部 |
| 完整时程 CSV | 自动识别 | 时间+幅值、元信息表头、保持单位，全部；要求 dt |
| 工程加速度 TXT | 自动识别 | cm/s²，纯幅值，明确选择加速度 |
| PEER AT2 | 自动识别 | AT2，g，明确选择加速度 |
| Modified miniSEED 工程 CSV | Modified，文件标定 | cm/s²，时间+幅值、元信息，明确选择加速度 |

内置配置只是快捷规则，不自动猜测输入单位、采样率或标定系数；缺少必要参数时应提示，不能宣称适合所有文件。用户可另存为自定义预设。

### 6.6 单文件工作区复用

在导入设置、导出区域或统一的预设入口中提供载入转换预设及从当前设置另存的能力。尽可能复用现有 `parse_dialog`、公共输入控件、`export_options`；不创建第二套解析/写出配置逻辑。

在打开文件前载入预设，可预填导入表单和后续输出配置，仍使用现有预览确认流程。已有文件时若只改变写出参数，可直接更新导出区；若改变读取、标定、缩放或解释参数，应从原始字节重新解析、使旧预览失效，并保留现有未导出编辑提示，不直接对现有 Trace 再执行标定或缩放。预设保存以实际采用的通用读取选项和当前写出选项为基础，逐通道手工编辑不自动写入预设；需要提示未纳入的文件相关内容。

## 7. M4：批量转换 Core

### 7.1 输入与执行范围

批量任务的基本单位仍是一个输入文件。CLI/GUI 负责收集明确的多个文件，或从指定目录按文件扩展名/glob 筛选（第一版建议仅支持文件名层面的 `*.ext`、`*` 等简单模式，不进行 shell 执行）。默认不递归，不自动扫描其他目录或跟随目录链接。

输入列表在任务启动前固定，目录筛选结果采用稳定排序，显式文件列表保留用户顺序。对同一实际文件去重并提示（规范化路径、可用的文件身份比较）；符号链接、硬链接及 Windows 路径大小写差异应纳入保护考虑。发现非法、不可读取或失效文件时记录明确的失败，不假装转换成功。空任务应拒绝启动。

所有输入使用相同的有效转换配置。对每个输入重新根据文件后缀生成 `extension_hint`，默认仍以实际内容识别格式。目录选择不等同于指定格式；没有统一解释规则的文件分成不同批次处理。

### 7.2 建议接口与执行过程

接口设计示意，具体类型由开发者结合现有 API 确定：

```cpp
struct BatchOptions {
    std::vector<std::filesystem::path> inputs;
    ConversionPreset preset; // 本次已解析并合并显式参数后的快照
    std::filesystem::path output_directory;
    bool overwrite{false};
};

// 逐文件结果含输入、终态、已写路径、通道数量、诊断；
// 批次结果含所有逐文件结果、汇总计数及停止状态。
BatchResult convert_batch(const BatchOptions& options,
                          /* optional progress callback, cancellation request */);
```

回调和停止机制使用 C++ 标准库或其他已有无 Qt 依赖的简单实现；不把 Qt 对象传入 Core。批量执行顺序：

1. 校验公共设置、输入清单和输出目录，建立本批次原始文件保护集合。
2. 取一个输入文件，使用 `load_file()` 和 `read()` 完成解析、标定、缩放及解释；不在后台同时载入全部文件。
3. 依据明确筛选规则选择 Trace，计算实际输出文件路径；检查本批次冲突与所有输入保护。
4. 复用已有 Writer、暂存和发布流程；记录警告、错误、部分发布及实际生成文件。
5. 释放该文件的字节、Trace 和编码缓冲，通知进度，再处理下一个输入。
6. 到达安全停止点或所有任务完成后返回汇总结果。

不要求单独把每个输入的完整波形保留在结果中。仅持有结果与有限诊断，必要时保留日志；不得在多个任务间共享可变 Trace 或修改原始文件。

### 7.3 输出路径与保护（关键任务）

批量输出统一为明确的目录，第一版采用平铺命名，延续现有 `<输入stem>_<安全通道名>.<扩展名>` 规则。已有 `files.cpp` 的通道名称去重、文件名合法化、单文件预检与暂存机制仍然有效。不要根据输出目录后缀把目录误判成指定输出文件；批量执行应明确指定目录语义。

当前 `export_file()` 只保护本次 input 并在内部生成路径。为避免复制命名逻辑，建议提取最小的共享“输出计划/路径校验”函数，供单文件导出和批量执行复用；让批量检查与实际发布使用完全相同的路径计划。不得另写一套近似命名函数，也不为了批量引入大型文件事务框架。

必须满足：

| 情形 | 行为 |
|---|---|
| 目标目录尚不存在 | 按明确目录语义创建；失败则给出诊断 |
| 已有目标文件 | 默认拒绝；本次显式允许覆盖时才考虑替换 |
| 目标与本批次任一原始输入相同 | 始终拒绝，含可识别的别名与链接；覆盖开关无权解除 |
| 批次内两个任务生成同一目标路径 | 禁止静默覆盖；按确定顺序保留先取得的目标，冲突任务失败并标明来源 |
| 文件名相同但来自不同目录或不同原格式 | 不假定一定冲突，按最终目标路径检查 |
| 已部分发布后发生文件系统错误 | 返回实际写出路径和部分成功状态；不虚报全部成功 |
| 读取或编码失败 | 遵循现有单输入暂存规则；不因另一个任务成功而隐藏错误 |

实际输出名称只有在读取通道元信息后才可确定，不要求启动前载入全部文件完成全批次预检。可先做轻量的重名风险提示，在每个文件解析后取得完整计划并在发布前检查。批次维护已保留的目标集合（至少覆盖已发布与部分发布的路径；首次预检/编码失败且未发布时可释放该任务的保留），同一路径不得由后续任务覆盖，即使用户显式允许覆盖既有外部文件。

使用绝对规范路径及适用的文件身份判断；对不存在的目标解析可用的父目录真实路径，考虑符号链接、硬链接、Windows 大小写不敏感及目标路径别名。发布前再次检查原件保护和覆盖条件，延续现有文件保护原则。无需承诺抵抗任意外部并发恶意修改，但应防止普通批处理过程中的误覆盖。批次不提供整体事务/回滚；已成功输出保留。

### 7.4 进度、状态与停止

以文件为进度单位，不虚构记录内部的精确百分比。文件状态建议使用：

| 状态 | 含义 |
|---|---|
| Pending | 等待 |
| Running | 正在处理 |
| Succeeded | 全部选中通道导出成功；允许附带警告 |
| Failed | 失败且没有发布结果 |
| Partial | 发布部分文件后失败 |
| Cancelled | 收到停止请求后未开始的文件 |

成功带警告与失败应明确区分；每项保留 `Diagnostic` 原文、已读取/选中/未选中通道数量（能够取得时）、实际写出文件路径以及失败阶段（读取、解析、筛选、路径检查、编码、发布等）。全局汇总区分成功、失败、部分成功、取消和警告；计数以文件为单位，输出文件数量单独显示。

第一版顺序执行，普通单文件失败继续下一项。对无法继续的公共配置或输出目录问题，在启动前拒绝批次或明确停止，不能把所有任务标记为成功。

停止采用协作式机制：收到停止请求后完成当前输入的转换与安全发布，再停止启动新文件；待执行项标记 Cancelled。GUI 显示“正在停止，当前文件完成后结束”，不使用强制终止线程，不删除此前成功结果，不承诺立即结束正在读取或编码的大文件。无需任务恢复和自动重试；用户可选择失败或未完成的输入重新组成新批次。

## 8. M5：CLI 集成

保留 `formats`、`info`、`convert`，新增 `batch`。CLI 语言保持英文，既有单文件输出与脚本兼容性不变。批量命令的 stdout/stderr 可采用明确的稳定英文格式：逐文件状态与实际写出路径、最终汇总；详细诊断通过 stderr。无需本轮增加复杂机器可读报告协议。

建议命令：

```sh
# 既有用法不变
xmake run gmtools info example/Trinidad.dat --profile example/trinidad.profile.json

# 单文件复用读写预设；目标格式可由预设提供
xmake run gmtools convert record.mseed --preset engineering_csv.json -o output/

# 显式覆盖本次输出单位，不修改预设文件
xmake run gmtools convert record.mseed --preset engineering_csv.json \
  --output-unit m/s2 -o output/

# 显式文件列表
xmake run gmtools batch record_A.mseed record_B.mseed \
  --preset engineering_csv.json -o output/

# 目录筛选（引号避免由 shell 提前展开）
xmake run gmtools batch --input-dir records --filter "*.mseed" \
  --preset engineering_csv.json -o output/

# 不使用预设，直接设置公共转换参数
xmake run gmtools batch --input-dir records --filter "*.at2" \
  --to csv --output-unit cm/s2 --text-layout time-values --text-header metadata -o output/
```

- `convert` 使用 `--preset FILE` 时可省略 `--to`，仍必须指定 `-o`；无预设则保留原有参数要求。`info --profile` 保持原状，本轮不要求为 `info` 增加读取转换预设的另一套入口。
- `batch` 支持显式文件列表或 `--input-dir DIR`，二者互斥。`--filter` 仅用于目录筛选，默认 `*`（普通文件）；最终输入清单、文件顺序与去重规则应明确。可提供 `--` 结束选项解析，确保带连字符的文件名可以处理。
- batch 可以采用共同的 ReadOptions/WriteOptions 显式参数；不带预设时必须指定可写目标格式。单次 UTC、NSLC/SID、相对起点和其他文件特定的覆盖参数在 batch 模式中明确拒绝。不得将一个文件的身份与时间批量应用到其他文件。
- 建议使用 `--select-quantity acceleration|velocity|displacement|counts|unknown` 表示明确导出筛选，允许显式 `--select-all` 清除预设筛选。与单文件 `--channel N` 不混用；对 convert 可复用这项导出筛选，保持其现有 `--channel` 读取/输出语义不变。
- `--overwrite` 必须由本次命令指定；预设、上次运行或其他任务不能授权覆盖。`batch -o` 必须为目录，不支持一次批次全部写入同一目标文件。
- 参数错误或公共配置无法启动返回非零；全部选定文件成功才返回 0。任一 Failed/Partial/Cancelled 返回非零（如实现 CLI 安全中断，可采用 130）；仅有警告仍可成功。继续处理后续文件不等于整体返回成功。无输入或无匹配不得返回伪成功。

参数最终拼写在实现中保持一致；优先复用现有 CLI 参数解析器及 Core 校验，避免将整个 CLI 重写为新的框架。补充 `--help`、命令示例与退出状态说明。

## 9. M6：GUI 预设与批量转换窗口

### 9.1 功能入口与工作区

保留现有单文件主窗口的三个主要区域（文件与通道、波形、参数与导出），不将多个输入文件的全部波形放入当前单文件工作区。主窗口标题栏或工具栏新增“批量转换 / Batch conversion”入口，未打开记录时同样可用；设置与预设管理入口位置应清晰，不堆积大量常驻按钮。

采用独立的批量转换窗口或对话框，第一版只允许运行一个批次；可使用模态窗口简化主窗口与任务之间的状态管理，不强制设计复杂多窗口架构。批量窗口关闭后保留主窗口原有波形、当前选择和未导出编辑，不替换其 `parsed_` 或 `last_options_`。运行批次期间，禁止重复启动任务、修改冻结配置及关闭仍在工作的窗口；如用户请求关闭，提示安全停止并在完成后允许关闭。主程序退出也应遵循相同约束。

### 9.2 文件清单

| 功能 | 实现要求 |
|---|---|
| 添加文件 | 支持多选文件，显示路径，采用统一去重规则 |
| 添加目录 | 目录与文件名筛选，默认不递归；先显示匹配结果，由用户确认 |
| 拖放 | 可复用当前拖放体验，多个文件进入批量清单；不改变原单文件拖放语义 |
| 移除所选 / 清空 | 仅修改任务列表，不删除磁盘文件 |
| 任务状态 | 文件、状态、输出数量、警告/错误摘要；详细路径与诊断可查看 |

文件清单应支持长文件名、Unicode 路径和同名不同目录的文件。格式尚未解析时可显示自动检测待处理或明确的输入格式配置，不仅凭扩展名宣称已识别成功。文件较多时不创建每个文件的波形控件。执行中列表、预设和输出设置只读；结束后可编辑并重新组成批次。

### 9.3 转换设置与执行确认

转换设置区域包括：预设选择/管理、编辑本次输入与写出参数、通道筛选、输出目录、覆盖选项。复用公共参数控件、`export_options` 和 Core 校验；不必将现有 `parse_dialog` 整体搬入批量窗口，不在批量配置阶段假装已经预览全部文件。需要查看具体文件时可在任务未运行时返回单文件工作区。

- 参数区提供当前有效设置的摘要，特别显示标定模式、数值缩放、输出单位和是否筛选通道；显式修改后标记为自定义或已修改预设。
- 对任意多文件不能预先确定共同物理量时，允许用户明确指定所需输出单位，提示不兼容输入会失败；不能因为缺乏预览而禁用一切输出单位选项，也不能推断单位。
- 文件级元信息编辑在批量通用设置中不显示或不可用；明确说明 UTC/NSLC 等由源文件提供，缺失需先通过单文件处理。
- 运行前确认输入文件数量、输出目录、有效规则与覆盖状态；对输出目录与输入目录重叠或文件名潜在冲突给出提示，实际路径安全检查由 Core 强制执行。
- GUI 选择 `quantity` 后，单文件工作区载入该预设时应明确反映为通道勾选，仍允许手动调整；批量中则对各文件独立应用规则。不能用第一个文件的勾选序号代表所有文件。

界面结构建议（仅为区域与信息关系，不要求逐字布局）：

```text
┌──────────────────── 批量转换 ────────────────────┐
│ 添加文件  添加目录  移除所选  清空          共 N 个文件 │
│ ┌─────────────────────────────────────────────┐ │
│ │ 文件路径             状态      输出数    摘要 │ │
│ │ ...                  等待        —       ... │ │
│ └─────────────────────────────────────────────┘ │
│ 转换预设 [当前预设             ]  管理 / 编辑设置 │
│ 输入格式 / 标定 / 缩放 / 输出格式 / 单位 / 筛选摘要  │
│ 输出目录 [                              ] 浏览  │
│ [ ] 允许覆盖已有目标（不包括原件及同批次目标）       │
│ 进度  [====================            ]  3 / N │
│ 成功 X · 失败 Y · 部分 Z · 取消 W · 输出文件 K     │
│ 查看详情     打开输出目录        开始 / 停止转换    │
└─────────────────────────────────────────────────┘
```

空间组织以实际主界面风格为准，采用可伸缩布局和现有主题，兼顾中英文文字长度。不得以固定宽度截断关键状态或将完整路径强制挤入窄列；可通过 tooltip 或详情查看。

### 9.4 后台任务与结果展示

使用当前 Qt Concurrent 或等价的现有后台机制，后台持有不可变批次配置快照和线程安全的停止标志。Core 回调只传递数据，不直接访问 QWidget；进度及结果通过队列连接、线程安全事件或 watcher 返回 GUI 线程。不能为更新进度频繁复制整个 `BatchResult` 或大规模波形。

开始后禁用输入与配置控件，显示当前文件与已完成文件数，停止按钮在有效状态下可用；停止请求发出后显示安全停止状态。任务终结后恢复控件并展示汇总，未运行项不得显示为成功。每个文件可查看完整诊断、选中/未选中通道数、实际发布的文件路径，部分成功须明确展示。支持打开输出目录、复制诊断或结果摘要；不要求建设独立的历史任务数据库或自动保存全部结果。

原有单文件导出仍通过现有后台机制运行，不能因增加批量入口而丢失预览复用、未导出修改提醒和绘图包络优化。翻译资源、主题和程序设置只影响展示，不影响后台数值和路径处理。

### 10.2 xmake 与资源

- `gmtools_core`：新增预设、批量模块，继续使用现有 C++20、nlohmann/json 和可选 libmseed；不得引入 Qt、Python 或额外大型依赖。
- `gmtools`：共用 Core，保持 Linux/Windows Unicode 路径支持与现有安装方式。
- `gmtools_gui`：新增 Qt GUI 源文件及翻译资源，保持 Widgets/Concurrent。依据实际 Qt SDK 的 Linguist 工具与 xmake 规则实现 `.ts` → `.qm` 的正常构建依赖、资源打包和安装；确保源翻译修改会触发重新编译。GUI 构建需要相关工具时给出明确错误，不影响 `--build_gui=n`。
- 保留 `--enable_mseed` 当前默认值和 SDK 校验。完整日常使用构建示例明确启用标准 miniSEED，精简 CLI 仍能读取 Modified miniSEED。
- 不将编译生成的 `.qm`、临时翻译清单、个人 SDK 路径、运行配置和批量输出提交仓库；若采用生成资源作为正式源码管理方式，需明确理由与更新机制，避免重复副本。

建议核对两种现有配置（路径以实际环境为准）：

```sh
# 完整 GUI 与标准 miniSEED
xmake f -m release --build_gui=y --enable_mseed=y --qt=/path/to/Qt/SDK --mseed_sdk=/path/to/libmseed
xmake build -j 4

# 精简 CLI，无 Qt 与 libmseed
xmake f -m release --build_gui=n --enable_mseed=n
xmake build -j 4 gmtools
```

两套配置可使用独立配置与产物目录，避免旧产物掩盖缺依赖问题。Windows 实际编译、安装及桌面操作按用户安排验证；未执行的范围应明确记录，不宣称所有平台均通过。

## 11. M7：验收方案

### 11.1 验收原则

下列用例为验收计划，不构成自动运行授权。开发者应按用户明确安排执行静态检查、编译或运行核查；未经授权不得启动测试、GUI、截图或视觉检查，不自动提交 Git。

优先复用现有四份示例文件（Helena AT2、Trinidad DAT、台湾 SAC、花莲 miniSEED）、Trinidad Profile 和可选武汉 Modified 实录；小型临时夹具用于路径冲突、异常输入和预设校验。无需建立大量新测试或完整组合矩阵。原文件保持不变，派生样本与输出置于新建的 `build/phase4/` 子目录，不写回原件或覆盖既有验收产物。

### 11.2 最小验收用例

| 编号 | 核查内容 | 验收标准 |
|---|---|---|
| T0 | 构建与基础回归 | 完整 Core/CLI/GUI 与精简 CLI 构建；翻译资源可用；原 formats/info/convert、Profile v1 及自描述文本读取无不相关变化 |
| T1 | 双语与程序设置 | 中英文主要界面、动态文本和新增对话框翻译；选择语言/主题后按约定生效，重启保持；系统回退明确；取消设置无副作用；路径、单位、JSON 字段和原始诊断不被翻译 |
| T2 | 转换预设 | 示例 JSON 加载、保存、再次载入及字段等价；错误版本、重复键、非法值、不适用选项明确拒绝；旧 Profile 保持可用；CLI 明确覆盖不修改原文件 |
| T3 | 单文件复用 | 使用相同规则显式转换与预设转换产生相同样本和主要元信息；改用不同单位/文本布局时符合现有语义；重新解释从原始字节执行，不重复标定/缩放 |
| T4 | 批量正常路径 | 使用至少两个输入文件、其中包含多通道文件；所有输出与独立单文件转换的数值、单位、采样及关键元信息一致；每 Trace 单文件；结果与实际文件对应 |
| T5 | 失败隔离与筛选 | 有效文件、无效文件、量纲不匹配文件组成一批，后续有效文件仍可完成；无匹配通道失败且零输出，未选中通道不隐式导出；提供武汉实录时验证加速度与辅助 counts 的显式筛选 |
| T6 | 输出安全 | 已有目标默认拒绝；显式覆盖仅允许外部目标；不同输入生成同名目标时拒绝后续冲突；目标与批次中尚未处理的源文件相同也拒绝；验证原始样本哈希不变；适用环境可核查链接与大小写别名 |
| T7 | 进度与停止 | 状态、警告、失败、部分发布（可通过受控文件系统错误或代码核查确认）及输出数量准确；停止后当前文件安全结束，未开始项标为取消；已写结果保留 |
| T8 | GUI 使用闭环 | 人工核查设置、预设管理及载入、批量多选/目录筛选、输出参数、进度与结果详情、停止，原单文件工作区保持；中英文布局与主题组合按实际桌面核查 |

T4/T5 选择实际易复现的少量数据即可；如果标准 miniSEED 未构建或武汉实录缺失，对相应用例标注 SKIPPED/BLOCKED，不把未执行路径写为 PASS。若运行旧 `scripts/verify_core_formats.py`，应使用新的输出目录，记录真实执行命令和状态；本轮不强制扩展该脚本为完整测试框架。

### 11.3 完成定义与交付

代码层面完成 M1–M6 的主要功能并集成至现有构建入口，更新 README、CLI help、双语词汇和预设示例。批量输出安全与配置语义必须有明确实现，不允许仅以 GUI 功能演示替代 Core 检查。

建议新增 `docs/validation/GMTOOLS_PHASE4_RESULTS.md`，记录实际开发基线、提交/工作树、构建配置、具体实现选择、验证命令、样本、结果及未完成事项。区分：

- `IMPLEMENTED`：已完成代码实现。
- `COMPILED`：指定配置实际编译通过。
- `PASS` / `FAIL`：实际运行或人工核查结果。
- `NOT RUN`：未获授权或尚未执行。
- `SKIPPED` / `BLOCKED`：样本、依赖或环境不满足，记录原因及解除条件。

不得使用历史第三阶段的 PASS 代替第四阶段新功能的验收。若暂时只完成静态检查与编译，应据实提交实现及待验证范围，不要求因本文件自行运行 GUI 或测试。已记录的 Windows、真实设备 wt/ws、正式 NIED 样本及示例数据再分发权等限制继续保留，不属于本阶段新增强制验收任务。

## 13. 实施提醒

1. 首先核对当前仓库和构建环境；先确定翻译机制与 Core 预设格式，再实现新界面。
2. 本轮新增默认方案为：语言与主题允许重启生效、批量平铺输出、顺序执行、独立批量窗口、同一批使用共同转换配置。为实际混合通道场景补充可选的显式物理量筛选，不自动丢弃辅助通道。

4. 开发结束报告实际改动、与方案的差异、检查结果及遗留事项。保持项目简洁和可维护性，不进行无关重构。
