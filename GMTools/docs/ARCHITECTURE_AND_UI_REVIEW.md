## 检查结论与处理

`FileData / Trace`、Qt-free 核心、静态格式表、标准文本复用数值解析器、逐通道暂存导出的结构符合当前工具规模。本次保留这些边界，核心公开接口、CLI 参数、格式适配器和数值换算规则未改动。

| 原有问题 | 本次处理 |
|---|---|
| `src/gui/main.cpp` 的 839 行混合启动、导入解释、参数表单、窗口状态和导出操作，难以独立维护。 | 入口只负责创建应用和窗口；主窗口、导入对话框、参数字段、绘图、主题与公共显示函数各自归属一个模块。 |
| 文件读取、完整解析及导出在 GUI 线程执行，大记录会阻塞事件处理。 | 使用 Qt Concurrent 执行耗时操作。工作函数持有输入所有权，完成回调在 GUI 线程更新控件；同时禁止重复启动或修改参与导出的数据。 |
| 波形控件保存 `Trace&`，替换解析结果或退出窗口时必须按特定顺序先销毁绘图控件。 | 控件只保存独立的显示数据及名称、单位、时长等小量字段，不再借用文档中的 Trace。 |
| 每次重绘都扫描完整样本，滚动、遮挡恢复和窗口调整会重复消耗时间。 | 解析工作线程预计算最多 4096 个极值桶，每个桶保留首值、末值、最小值和最大值；绘制进一步按宽度合并桶。完整数组仅供核心和导出使用。 |
| 点击确认会重复解析已经预览成功且参数未变化的文件。 | 缓存成功预览；表单修改立即使缓存失效。参数未变化时直接采用该结果。 |
| GUI 载入 Profile 用值比较推断哪些字段来自上一次配置，清空字段与未指定字段混在一起。 | GUI 载入配置直接替换表单，包括清空未指定项；随后允许手动调整。CLI 保留显式参数覆盖 Profile 的语义。 |
| 主窗口多个长文本框并列，来源字段、摘要和诊断难以区分。 | 三栏工作区分开文件/通道、波形、参数/导出；详情采用 Summary、Metadata、Diagnostics 页签。 |
| 无通道勾选时仍可点击导出；选中通道与波形之间没有定位反馈。 | 导出按钮显示数量并在零选择时禁用；选中通道定位、高亮相应波形。 |
| 输出默认单位含义不明确，元数据损失通常等到导出后才能看到。 | 用 Keep input unit 明确默认行为，AT2 明示固定 g；目标格式旁显示必要参数和元数据限制，完整诊断仍保留在导出结果中。 |
| 输入单位重标记容易与数值换算混淆。 | 编辑对话框明确说明输入单位只解释现有值，实际换算在导出区选择；额外 Numeric factor 独立于文本布局，并能用于 K-NET 标定后的调幅。 |
| 覆盖开关会跨记录沿用，新文件或关闭窗口可能丢失通道编辑。 | 每次接受新解析重置覆盖开关；替换或关闭带未全部导出编辑的记录时提示。 |

## 模块职责

```text
src/core/ + src/formats/       数据模型、读写、校验、Profile、文件发布（Qt-free）
src/cli/main.cpp              CLI 参数与结果展示
src/gui/main.cpp              QApplication、主题与窗口入口
src/gui/main_window.*         当前记录、通道选择、检查和导出交互
src/gui/parse_dialog.*        输入解释表单、预览缓存、Profile 及建议
src/gui/override_fields.hpp   导入与通道编辑共用的参数控件
src/gui/background_task.hpp   工作线程执行、异常结果及 GUI 线程回调
src/gui/plot.*                有界显示包络及波形绘制
src/gui/ui_helpers.*          字符串、数字、诊断与参数输入转换
src/gui/theme.*               配色和控件样式
```

后台读取持有文件路径副本，后台解析持有原始文件的共享只读所有权。主窗口只在导入对话框确认成功后替换当前记录，因此读取失败、解析失败和取消导入都保留旧记录。导出持有当前解析结果的共享所有权；执行期间窗口禁止编辑、替换记录及关闭。工作线程不读写控件。

显示包络是波形概览，不用于写出，也不执行滤波、重采样或物理单位换算。编辑名称、单位和采样参数只更新图表说明，不重新扫描原始波形。

本轮仍使用一次读取完整文件、每条 Trace 保存完整样本的方式，没有增加流式解析、任务取消、批量转换或格式插件框架。长任务可显示忙碌状态，但需要等待操作完成才能关闭当前工作窗口。许多通道同时显示、较低分辨率和高 DPI 的实际体验仍需人工确认。

## 构建记录与验证边界

Linux Release 编译环境为 GCC 16.2.1、Qt 6.12.0、nlohmann/json 3.12.0；可选适配器使用本机已有的 libmseed 3.5.3。GUI 新增 Qt Concurrent 链接依赖，纯 CLI 仍不需要 Qt。

```sh
cmake -S . -B build/review-ui -DCMAKE_BUILD_TYPE=Release \
  -DGMTOOLS_BUILD_GUI=ON -DGMTOOLS_ENABLE_MSEED=ON \
  -DCMAKE_PREFIX_PATH=/tmp/gmtools-libmseed-sdk \
  '-DCMAKE_CXX_FLAGS=-Wall -Wextra -Wpedantic'
cmake --build build/review-ui -j 4

cmake -S . -B build/review-cli -DCMAKE_BUILD_TYPE=Release \
  -DGMTOOLS_BUILD_GUI=OFF -DGMTOOLS_ENABLE_MSEED=OFF \
  '-DCMAKE_CXX_FLAGS=-Wall -Wextra -Wpedantic'
cmake --build build/review-cli -j 4
```

`/tmp/gmtools-libmseed-sdk` 是本机现有依赖目录，其他环境应替换为自己的安装路径。

## 建议的人工检查

1. 查看空状态、浅色/深色主题、小窗口和高 DPI；导入四份已有样本，检查原文、诊断和所有通道的布局。
2. 通用文本先载入 Trinidad Profile，再载入字段较少的配置，确认旧字段清空；更改参数后确认旧预览不可直接采用，Apply text suggestions 仍需主动点击。
3. 勾选、清空和选择通道，核查导出数量、波形定位、时间轴及未知单位；编辑后保持勾选与滚动位置，并核查输入单位重标记和输出单位换算的区别。
4. 检查多通道导出、目标冲突、覆盖开关重置和失败后的实际文件列表；核查导出数值仍来自完整样本，而非图表包络。
5. 用较大文件观察后台读取、解析与导出；操作期间尝试替换/关闭，确认结束后能够继续操作；取消新文件导入后旧记录仍可使用。
